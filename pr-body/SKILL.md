# PR Body

Write PR bodies that are easy for maintainers to review: say why the change exists, group implementation by files or components, state the test plan clearly, and skip low-value boilerplate.

## Sections

Prefer this structure unless the user asks for a different project template.

### Title

- Concise and reviewer-facing; no generated-by labels like `[codex]`.
- Prefer the repository's existing PR title style when clear from history.

### Summary

- Prose, not bullets; a few sentences.
- Say why the change exists and what problem it fixes.
- Put `Fixes #123` after the paragraph when there is an issue reference.

### Details

- Always use the exact heading `## Details`.
- Group bullets by file, workflow, or component under `###` subheadings.
- Start bullets with strong verbs (`Add`, `Remove`, `Update`, `Align`, `Refactor`).
- Summarize related edits; do not restate every diff line.

### Breaking Changes

- Include only when the PR genuinely breaks something; omit otherwise.
- Keep entries direct and actionable, including required user action when known.

### Test Plan

- Always include this section, using the exact heading `## Test Plan`.
- Use a checklist: `- [x]` for completed checks, `- [ ]` for planned or required ones.
- Name exact commands or workflows. If no local testing was run, say so plainly.

### Signature

- Always end the body with `Generated by <agent> (<model>)`, substituting the current agent's name.
- Use the most accurate model family rather than inventing a precise version.

## Style

- Plain technical language; blank line after headings.
- No optional sections (`## Risks`, `## Follow-ups`, screenshots, migration notes) unless the user asks.
- Do not claim testing or follow-up work that did not happen.

## Example

```md
## Summary

This PR aligns the certification workflows with the execution environments they are meant to validate against. It removes redundant sanity job configuration and makes the expected Python baseline explicit.

Fixes #76

## Details

### `certification-reusable.yml`
- Remove the per-version sanity input so `ansible-test` covers supported Python versions automatically.
- Hard-code the supported stable branches used by downstream execution environments.

### Calling workflows
- Update the reusable workflow callers to stop passing the removed input.

## Test Plan

- [x] `zizmor` passes locally.
- [ ] CI passes for the PR workflow matrix.
- [ ] Sanity jobs run for each supported stable branch.

Generated by <agent> (<model>)
```
